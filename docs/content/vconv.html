vconv is the numerical core of the image-super-resolution path. It is a CPU implementation of square-kernel convolution with stride and zero padding, the common activations, ESPCN pixel shuffle, a weight-bundle loader, and explicit backward kernels for training. The loops live in vyne/runtime/modules/vconv.h; this library is the typed wrapper.

 vyne snippetvyne
use external "vconv/vconv.vy"; x :: vconv.Tensor := vconv.tensor(pixels, height, width, channels); y :: vconv.Tensor := vconv.conv2d(x, weights, bias, 64, 5, 1, 2); y = vconv.tanh(y); y = vconv.pixel_shuffle(y, 2);

Layout

Tensors are HWC, the same layout as vimage.Image:

 snippettext
index = (y * width + x) * channels + c

Conv weights use PyTorch's OIHW order:

 snippettext
index = (((oc * in_c) + ic) * kernel + ky) * kernel + kx

That means a torch.nn.Conv2d state dict exports without a transpose. Bias is a length-out_channels vector.

Output shape for convolution:

 snippettext
out_h = (in_h + 2*pad - kernel) / stride + 1 out_w = (in_w + 2*pad - kernel) / stride + 1

pixel_shuffle requires channels % scale^2 == 0 and maps input[y][x][c*scale^2 + i*scale + j] to output[y*scale + i][x*scale + j][c].

Backward (training)

FunctionResult

weight in conv_backward_input is passed as an Array so the wrapper stays outside the native-array ABI.

vconv.load_model(path) reads a bundle into a Map of name -> Array<Float64>. Two formats are accepted:

Binary .vwy (preferred):

 snippettext
"VYW1" u32 tensor_count repeat: u32 name_length, u8[] name u32 ndim, u32[] dims f32[] values

Text .vwt (fixtures and hand editing):

 snippettext
VYWT1 <tensor_count> <name> <ndim> <d0> <d1> ... <values...>

vconv.get_tensor(model, name) throws when a tensor is absent or empty. scripts/export_espcn_weights.py converts a PyTorch ESPCN checkpoint to .vwy and also writes the deterministic passthrough model used by the example.

Shape validation

conv2d, tensor, pixel_shuffle, and the activation wrappers check shapes before touching the kernel and throw a Vyne error on a mismatch. The native functions themselves return an empty array on invalid input, so the wrapper is the only place a caller needs to reason about.

Limits

  • vconv.conv2d is CPU. The @device backend now has device_conv2d; the SR project uses it for full-device inference, while vconv itself does not auto-dispatch. Training uses the CPU backward kernels.
  • Backward is CPU-only and covers the square-kernel stride/pad cases above.
  • No dilation or groups yet.
  • Naive direct convolution. It is fast enough for the ESPCN demo on modest images, not for real-time 1080p->4K.

Backend support

vconv is a native runtime module. Use the compiled backend (vynec --compile). The AST interpreter does not bind the convolution kernels yet; that is tracked with the other native-module interpreter gaps.
