CLI Reference

Every vynec command and flag, project discovery, Arduino upload, and benchmark reports.

 text snippettext
vynec <script.vy> [flags] compile and run vynec <mode> <script.vy> [flags] explicit mode vynec build [path] build the current project vynec run [path] build and run the project vynec bench [file] benchmark project targets vynec init [path] scaffold a new project

Execution modes

FlagEffect
(none)Compile and run
--runCompile and run
--astInterpret directly; no C emitted
--verifyHash-check source, then interpret
--compileEmit C and compile a binary; stop
--emit-cWrite .vy.c; do not invoke the host compiler
--emit-asmWrite .vy.s via the host compiler
 shell snippetshell
vynec --ast script.vy vynec --compile script.vy vynec --emit-c script.vy vynec --emit-asm --native script.vy

Arduino

FlagEffect
--arduino <board>Target Arduino; currently uno
--arduino-flash / --flashUpload the built .hex with arduino-cli
--monitorOpen arduino-cli monitor after flashing
--port <device> / --device-port <device>Serial port, for example COM3
--baud <rate>Monitor baud rate; default 115200
--fqbn <string>Override the board identifier
 shell snippetshell
vynec --arduino uno sketch.vy vynec --arduino uno --flash --monitor --port COM3 sketch.vy

--arduino uno alone produces .elf and .hex. --flash and --monitor are post-build actions.

Projects

 shell snippetshell
vynec build vynec run vynec build examples/projects/srcnn vynec run examples/projects/srcnn

Without a path, the driver walks up from the current directory until it finds project.toml, then uses src/main.vy, then main.vy. Project configuration is applied before explicit CLI flags, so flags still win.

See Projects & Tooling for the manifest schema and templates.

Benchmark

 shell snippetshell
vynec bench vynec bench src/main.vy --warmup 5 --iterations 200 vynec bench --report build/bench.json
FlagEffect
--warmup <n>Warm-up runs before measuring
--iterations <n>Measured runs
--report <path>Override the JSON report path

Project benchmarks use [bench] from project.toml. Board targets are skipped. Single-file mode writes <stem>_bench.json next to the source unless --report is given.

Init

 shell snippetshell
vynec init vynec init --name demo --kind ml --no-git vynec init --help
FlagEffect
--name <name>Project name; suppresses the TUI
--kind <kind>blank, ml, embedded, scientific, sr, mixed
--targets <list>desktop, arduino-uno, coral, jetson
--libraries <list>Comma-separated library names
--cuda yes|noWrite [device.cuda]
--license <id>AGPL-3.0-only, MIT, proprietary
--yesAccept defaults
--no-tuiForce non-interactive
--no-gitSkip git init and the initial commit

Exit codes: 0 success, 1 cancel, 2 non-interactive without a name or a terminal smaller than 80×24, 3 project.toml already exists, 4 generation or configuration error.

Exit codes

CodeMeaning
0Success
1Compilation or runtime error
2CLI misuse

Diagnostics go to stderr. Color is enabled only when stdout is a terminal and NO_COLOR is unset.
