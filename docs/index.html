The Vyne language

A small, statically typed language with arena-based memory, explicit lexical regions, and a C transpiler backend. No GC pauses. No manual free. Build games, audio tools, and web servers from one toolchain.

0GC pauses
1compiled target: C
11standard modules
~3mshello-world compile

What Vyne is

Vyne is a general-purpose programming language designed around one idea: memory lifetime should be visible in the source code, and it should not be a garbage collector's job. You tell the compiler where a chunk of work begins and where its scratch memory ends. The runtime does the rest.

The language draws its surface syntax from C, Lua, and Python — C-style operators, Lua-style iteration with through ... loop, and Python-like string formatting. Under the hood, every Vyne program is lowered to a single C translation unit and handed to a C compiler. That means Vyne runs at native speed without a runtime interpreter, and it interops trivially with any C library you can link.

Design goals

Predictable memory
Regions give you explicit control over when scratch memory is reclaimed. No GC sweeps, no pauses, no surprises.
Small surface
One file format, one type system, no metaprogramming, no macros. Learn the whole language in an afternoon.
Native code
Everything compiles to C, which compiles to machine code. No interpreter overhead, no JIT warm-up.

What you need to know first

This manual assumes you are comfortable with at least one curly-brace language (C, JavaScript, Go, Rust, or similar). If you can read for (int i = 0; i < n; ++i) { ... } and know what null means, you are ready.

No interpreter mode
As of v0.0.4, Vyne only compiles to C. Earlier releases also shipped a tree-walking interpreter for fast iteration; that path has been removed. If you find a reference to --interp anywhere in the docs, it is stale — please report it.

How the compiler runs

You write .vy files. The vynec compiler runs three stages:

  1. Lexer + parser. Source text becomes an abstract syntax tree.
  2. Semantic analysis. Types are checked, symbols resolved, regions validated. Diagnostics are reported with source-context carets.
  3. C emission. The AST is lowered into a single C translation unit that includes vyne_runtime.h and any module headers you imported. That C file is then compiled by your system C compiler (GCC, Clang, or MSVC) and linked into a standalone binary.

You never see the generated C unless you want to. The compiler cleans it up by default.

Where to go next

If you want to start writing code immediately, jump to Hello, World. If you want to understand the whole language before writing anything, Language Tour is a single pass over every construct you will meet in practice.

Getting Started

Installation

Vyne has no runtime dependencies beyond a C compiler. Install once, use everywhere.

Prerequisites

  • A C11-compatible compiler: GCC 11+, Clang 14+, or MSVC 19.30+.
  • make (or an equivalent build tool for your platform).
  • Linux, macOS, or Windows 10+.

Build from source

 shell
# Clone git clone https://github.com/t2ncay/vyne.git # Build the compiler cd vyne make # Add to PATH (Linux / macOS) export PATH="$PWD/bin:$PATH"

After this, vynec is on your path. Verify it:

 shell
vynec --version # → vynec v0.0.4 (C backend)

Compiling a program

The compiler takes a .vy file and produces an executable:

 shell
vynec hello.vy ./hello

Two flags are worth remembering on day one:

Flag Effect
--emit-c Write the intermediate C file to disk for inspection.
--keep Keep intermediate artifacts (the .c file and object files) after linking.
On first compile
The first time you compile any program, vynec will build its runtime support headers into a local cache. This adds a few seconds to the first build and nothing to subsequent ones.
Getting Started

Hello, World

The smallest Vyne program is one line.

 hello.vy vyne
out("hello, world");

Save it as hello.vy, then:

 shell
vynec hello.vy ./hello # → hello, world

Reading it line by line

out is a built-in function. It takes any value, converts it to its display form, and writes it to standard output followed by a newline. It is not a keyword — it is defined by the runtime — but it is globally available and never needs to be declared.

"hello, world" is a string literal. Strings in Vyne are immutable and UTF-8.

The trailing ; is a statement terminator. Vyne does not have automatic semicolon insertion, so you always write it.

With a variable

 hello2.vy vyne
// `::` declares the type; the value infers the rest. greeting :: String = "hello"; name :: String = "world"; out(greeting + ", " + name + "!");

:: is Vyne's type-annotation operator. It reads naturally: "greeting is a String". Once a variable has a type, its storage layout is fixed for its lifetime — reassigning a String to an Int64 will be a compile error.

String concatenation
The + operator concatenates when at least one side is a String. This is the only implicit coercion Vyne performs; everything else requires an explicit conversion with string(), int64(), or float64().
Getting Started

Language Tour

One page, every construct. Read this end-to-end and you will recognise any Vyne file you meet.

Values

Vyne has four primitive types — Int64, Float64, Bool, Null — and four composite ones: String, Array, Map, and Struct (declared with the interface keyword).

tour.vy — valuesvyne
count :: Int64 = 42; ratio :: Float64 = 3.14; ready :: Bool = true; nothing :: Null = null; name :: String = "vyne"; items :: Array = [1, 2, 3]; pair :: Map = { "x": 1, "y": 2 };

Control flow

Familiar if and while, plus a distinctive iteration construct called through. There are five modes: loop (side effects), collect (map), filter, every (all), and unique (dedupe).

tour.vy — controlvyne
if (count > 10) { out("big"); } else { out("small"); }; // Loop over a range, side effects only through i :: 1..5 -> loop { out(i); }; // Map: multiply every element by 2 doubled :: Array = through x :: [1,2,3] -> collect { x * 2 }; // Filter: keep only even numbers evens :: Array = through n :: 0..10 -> filter { n % 2 == 0 };

Functions

Declared with fn. Parameters can be typed with ::; return type after ->.

tour.vy — functionsvyne
fn add(a :: Int64, b :: Int64) -> Int64 { return a + b; }; // Return type and param types are optional in dynamic mode fn double(x) { x * 2 }; out(add(2, 3)); // → 5 out(double(7)); // → 14

Structs via interface

Vyne has no separate struct or class keyword. An interface block declares fields and methods together, and doubles as a positional constructor.

tour.vy — interfacevyne
interface Circle { r :: Float64; area() -> Float64 { return r * r * 3.14159; }; }; c :: Circle = Circle(4.0); out(c.area()); // → 50.26544

Memory and regions

Regions are the reason Vyne exists. A region block marks a lexical scope whose scratch allocations are released on exit. Values you need to keep past the region boundary are marked with region.commit.

tour.vy — regionsvyne
through epoch :: 1..1000 -> loop { region scratch { xs :: Array = [epoch, epoch + 1, epoch + 2]; msg :: String = "epoch:" + string(epoch); // msg survives the region; xs does not. region.commit(msg); }; out(msg); };

On every iteration, everything allocated inside scratch is reclaimed at the closing brace — except msg, which was committed. Total memory usage stays flat regardless of iteration count.

Error handling

try / catch / finally work the way you expect, with a jump-buffer implementation.

tour.vy — errorsvyne
try { risky(); throw "boom"; } catch (err) { out("caught: " + err); } finally { out("cleanup"); };

Modules

The module keyword pulls a built-in library into scope. group organises your own code into namespaces. use imports another file.

tour.vy — modulesvyne
module vmath; module vcore; r :: Float64 = vmath.sqrt(16.0); out(r); // → 4.0

That is the whole language in a page. The remaining chapters in Language Reference expand each section with edge cases and formal rules.

Language Reference

Values & Types

Vyne has eight value kinds. Four are primitives stored inline; four are composites stored behind a reference.

Primitive types

Type Storage Range / notes
Int64 8 bytes, signed −2⁶³ to 2⁶³ − 1
Float64 8 bytes, IEEE 754 Double precision
Bool 1 byte true / false
Null 0 bytes of payload The absence of a value

Primitives are copied by value at every assignment, return, and parameter pass. There is no boxing overhead for primitives used in their native type — the compiler emits int64_t, double, or bool directly.

Composite types

Type Notes
String UTF-8, immutable. Stored as a pointer to a NUL-terminated byte sequence.
Array Heterogeneous, growable. Elements are 16-byte tagged values.
Array<T> Typed, unboxed. Array<Int64> and Array<Float64> store elements as raw int64_t/double. Significantly faster and smaller than the generic Array.
Map String keys only. Open-addressed hash table with tombstones. Iteration order is unspecified.
Struct Declared via interface. Contains named fields and method bindings.

Typed vs. untyped arrays

This is the single most consequential typing decision you will make.

Array (boxed)
Each element is a 16-byte tagged union. Any value of any type can live alongside any other. Convenient, slower, larger.
Array<T> (typed)
Elements stored contiguously in native layout. Array<Float64> of length N occupies exactly 8N bytes. Ideal for numerics.
arrays.vyvyne
// Boxed — mixed types allowed mixed :: Array = [1, "two", 3.0]; // Typed — all elements same type, unboxed xs :: Array<Int64> = [1, 2, 3, 4]; ys :: Array<Float64> = [1.0, 2.0, 3.0]; // Both share the same indexing syntax out(xs[0]); // → 1
How to decide
If every element has the same numeric type, always prefer Array<T>. Fall back to plain Array only when you genuinely need heterogeneous elements (or a dynamic type the compiler cannot prove).

Strings

Strings are immutable. Every operation that "modifies" a string returns a new one. The compiler picks one of two storage strategies:

  • Static strings — literals like "hello" are emitted into read-only memory. Free, no allocation, no lifetime concern.
  • Arena strings — the result of concatenation, substring, formatting, and so on, lives in the current arena. Its lifetime is bounded by the enclosing region.

From Vyne source, this distinction is not observable. "hello" and "hel" + "lo" produce values that compare equal and behave identically. But the latter allocates, and if you are inside a hot loop, that matters.

Null and absence

null is a first-class value. Reading an out-of-bounds array index yields null, as does reading a missing map key. The null-coalescing operator ?? and its assignment form ??= exist to make handling this ergonomic:

null.vyvyne
name :: String = lookup("missing") ?? "anonymous"; cfg.mode ??= "default"; // assign only if currently null

Type inference

The compiler infers a variable's type from its initializer when you write = alone. The :: operator asserts a type explicitly. Under strict mode (the default), you must use ::; dynamic mode relaxes this.

inference.vyvyne
x = 42; // x : Int64, inferred y :: Float64 = 42; // y : Float64, explicit (implicit int → float widening)
Language Reference

Literals & Expressions

Numeric, string, array, map, and range literals, plus the full operator set.

Numeric literals

numbers.vyvyne
42 // Int64 3.14 // Float64 0.5 // Float64

Vyne does not currently support hexadecimal, binary, or scientific-notation literals in source. Use vcore.hex_to_int64("0xFF") when you need to read a hex value from text.

String literals

Strings use double quotes. Escape sequences are C-compatible:

Escape Meaning
\n Newline
\t Tab
\r Carriage return
\\ Backslash
\" Double quote
\{ \} Literal braces (suppresses interpolation)
\ooo Up to 3 octal digits

Interpolated strings

Any {expr} inside a string is evaluated and converted to text:

interp.vyvyne
name :: String = "Ada"; score :: Int64 = 99; out("Player {name} scored {score}"); // → Player Ada scored 99

Array literals

arrays.vyvyne
empty :: Array = []; numbers :: Array = [1, 2, 3]; mixed :: Array = [1, "two", 3.0, null];

If every element is the same numeric type (Int64 or Float64), the compiler materialises the literal as a typed, unboxed array. Otherwise, it falls back to the boxed form.

Map literals

maps.vyvyne
point :: Map = { "x": 1, "y": 2 }; out(point["x"]); // → 1

Keys must be string literals at the literal site. Runtime lookup with a computed string key is fine — m[keyVar] — but the map literal syntax itself only accepts literal strings.

Ranges

The .. operator constructs an inclusive range. It is most useful inside through:

ranges.vyvyne
through i :: 1..10 -> loop { out(i); }; // As a value, it produces an array xs :: Array = 1..5; // [1, 2, 3, 4, 5]

Operators

Vyne inherits C's operator set and adds a handful of its own. Precedence, lowest to highest:

Level Operators Associativity
1 ?: right
2 ?? right
3 |> left
4 || left
5 && left
6 == != left
7 in left
8 < <= > >= left
9 .. left
10 + - // % left
11 * / ** left
12 ! - $ prefix
13 ++ -- postfix

Arithmetic

+ - * / are the familiar four. Two extras:

  • // — floor division. Truncates toward negative infinity on Int64 (matching C's / is not what it does — Vyne is C-truncating here for consistency; the name is historical).
  • % — modulo. Always matches the sign of the left operand.
  • ** — exponentiation. Always returns Float64, even for integer operands.

Comparison

== performs deep equality on composite values: two arrays with the same elements are equal, two maps with the same key-value pairs are equal. For reference types you do not get pointer identity unless both sides are the same underlying value.

Logical

&& and || short-circuit. Any value is truthy except null, false, 0, 0.0, and the empty string.

Membership

x in collection works for arrays (element search), maps (key search), and strings (substring test).

Pipeline

value |> fn(args) is sugar for fn(value, args). It lets you write data-flow chains without nesting:

pipeline.vyvyne
// These are equivalent: result :: Array = sort(filter(xs, isPositive)); result :: Array = xs |> filter(isPositive) |> sort();

Ternary and null-coalesce

ternary.vyvyne
label :: String = ready ? "go" : "wait"; display :: String = name ?? "anonymous";
Language Reference

Variables & Assignment

Declaration, type annotation, reassignment, and mutability rules.

Declaration syntax

The form is name :: Type = expression;. The type annotation is mandatory under strict mode and optional under dynamic mode. The initializer is optional only when the type has a default (primitives, empty array, empty map, empty string).

vars.vyvyne
// Explicit count :: Int64 = 0; label :: String = ""; xs :: Array = []; // Default-initialised (no initializer) ready :: Bool; // false total :: Int64; // 0 ratio :: Float64; // 0.0 // Inferred (dynamic mode only) x = 42; // x : Int64

Reassignment

Use = to reassign an existing variable. Its type is fixed at declaration; assigning a value of a different type is a compile error.

reassign.vyvyne
x :: Int64 = 1; x = 2; // OK x = "hello"; // Compile error: cannot assign String to Int64

Constants

Prefix a declaration with const to make it read-only. Reassignment of a const is a compile error.

const.vyvyne
const pi :: Float64 = 3.14159; // pi = 3.0; // Compile error

Indexed assignment

Arrays and maps support element assignment with the same [] syntax used for reads.

indexed.vyvyne
xs :: Array = [1, 2, 3]; xs[0] = 99; // OK m :: Map = { "a": 1 }; m["b"] = 2; // inserts "b"
Out-of-bounds writes are silent
Writing to an array index that is out of range is a no-op — it does not throw, grow the array, or report an error. Always ensure your index is valid before writing.

No destructuring

Vyne does not support destructuring assignment. The following is not valid:

nope.vyvyne
// NOT valid Vyne [x, y] = pair; // ✗ { a, b } = map; // ✗

Assign each element individually instead.

Scope

Variables live in the block where they are declared. Blocks are introduced by { ... }, function bodies, loop bodies, and region bodies. A variable declared inside a block is not visible outside it.

scope.vyvyne
x :: Int64 = 1; { y :: Int64 = 2; out(x + y); // → 3, outer visible }; // out(y); // Compile error: y not in scope
Language Reference

Control Flow

Conditionals, loops, and Vyne's distinctive through iteration.

if / else

Conditions must be parenthesised. Braces are required for both branches; there is no single-statement form.

if.vyvyne
if (score >= 90) { out("A"); } else if (score >= 80) { out("B"); } else { out("C"); };

while

while.vyvyne
i :: Int64 = 0; while (i < 10) { out(i); i++; };

through — the iteration construct

Vyne's through is a general iteration primitive that bundles looping with collection production. The syntactic shape is: 

through name :: iterable -> mode { body };

The five modes have distinct semantics:

Mode Body result used for Returns
loop — last body value (rarely used)
collect new array element Array of body results
filter keep/discard predicate Array of kept source elements
every predicate, short-circuits on first false Bool
unique — Array of deduplicated source elements

loop

Side effects only. Most common when you want to do something N times.

loop.vyvyne
through i :: 1..5 -> loop { out("iteration " + string(i)); };

collect

Transform each element. The body's value becomes the corresponding output element.

collect.vyvyne
squares :: Array = through x :: 1..5 -> collect { x * x }; // → [1, 4, 9, 16, 25]

filter

Keep source elements for which the body is truthy.

filter.vyvyne
evens :: Array = through n :: 0..10 -> filter { n % 2 == 0 }; // → [0, 2, 4, 6, 8, 10]

every

Does every element satisfy the predicate? Short-circuits at the first false.

every.vyvyne
allPositive :: Bool = through x :: [1, 2, 3] -> every { x > 0 }; // → true

unique

Deduplicate preserving first-seen order.

unique.vyvyne
distinct :: Array = through x :: [1, 2, 1, 3, 2] -> unique { }; // → [1, 2, 3]

break and continue

Both work inside any loop. Both must unwind any live regions on the way out — that happens automatically:

break.vyvyne
through i :: 1..100 -> loop { region scratch { xs :: Array = [1,2,3]; if (i == 5) { break; }; }; };
break / continue inside try — not supported
You cannot use break or continue to exit a try block. The compiler rejects this with a clear error. Use a flag variable and check it after the try/catch/finally has run.

Ternary expression

cond ? a : b is an expression, not a statement — usable anywhere a value is expected.

Functions

Declaration, parameters, return values, and named arguments.

Declaration

Functions start with fn. The parameter list can annotate each parameter's type with ::. The return type follows ->. Both are optional; missing types default to dynamic.

fn.vyvyne
fn add(a :: Int64, b :: Int64) -> Int64 { return a + b; }; // No types — dynamic mode only fn square(x) { x * x }; // Explicit null return fn log(msg :: String) -> Null { out(msg); };

return

A function without an explicit return returns null. A bare return; is equivalent to return null;.

If a function is inside a region, returning a non-primitive value is handled specially — see Memory & Regions.

Named arguments

At the call site, you can supply arguments by name. You cannot mix positional and named arguments in the same call.

named.vyvyne
fn draw_box(x :: Int64, y :: Int64, w :: Int64, h :: Int64) -> Null { // ... }; // Both valid: draw_box(10, 20, 100, 50); draw_box(x: 10, y: 20, w: 100, h: 50);

Recursion

Functions can call themselves. Vyne does not perform tail-call optimisation, so deep recursion is bounded by the C stack.

Type parameters experimental

Function-level generic parameters exist syntactically (fn max<T>(...)) but the emitter's instantiation strategy is not yet complete. Do not depend on it in production code; the syntax may change before v0.1.

Functions on interfaces

Methods are declared inside interface blocks — see the next chapter.

Language Reference

Interfaces (Structs)

Vyne's only user-defined composite type. Doubles as a positional constructor.

Declaration

An interface block declares named fields and, optionally, methods. The block itself becomes a constructor callable with positional arguments.

shapes.vyvyne
interface Circle { r :: Float64; area() -> Float64 { return r * r * 3.14159; }; circumference() -> Float64 { return 2.0 * 3.14159 * r; }; }; c :: Circle = Circle(4.0); out(c.area()); // → 50.26544 out(c.circumference()); // → 25.13272

self

Inside a method, self refers to the receiver. Field access is implicit — you can read r directly — but the compiler will also accept self.r for clarity.

Field access and mutation

mutate.vyvyne
c :: Circle = Circle(1.0); out(c.r); // → 1.0 c.r = 5.0; // field assignment out(c.area()); // → 78.53975

Module binding

An interface declared inside a group or with an explicit :: Module suffix becomes part of that namespace.

grouped.vyvyne
group Shapes { interface Point { x :: Float64; y :: Float64; }; }; p :: Shapes.Point = Shapes.Point(1.0, 2.0);

Introspection

obj.fields() returns an array of field names as strings. Useful for debugging and generic serialisation.

Typed array fields

Fields can be declared as Array<T> for unboxed storage:

typed-fields.vyvyne
interface Matrix { data :: Array<Float64>; rows :: Int64; cols :: Int64; };

Value semantics

Structs behave as values: assigning one struct to another copies its fields. Methods are shared — the method table is not duplicated.

Deep copy on assignment
Struct assignment deep-copies any nested arrays or maps. This can be expensive for large structs. If you need shared mutation, wrap the struct in a container or use Array/Map fields, which follow normal array/map reference semantics.

Groups & Modules

Namespacing, imports, and the built-in module system.

module — pull in a built-in

Every built-in library must be declared before use. A module statement brings its names into scope.

modules.vyvyne
module vcore; module vmath; out(vmath.sqrt(16.0));

group — user namespaces

Groups organise related declarations. They can nest.

groups.vyvyne
group Physics { gravity :: Float64 = 9.81; group Constants { lightSpeed :: Float64 = 299792458.0; }; }; out(Physics.gravity); out(Physics.Constants.lightSpeed);

use — import another file

use reads a .vy file and executes it in a fresh module scope. Its top-level bindings become members of a namespace named after the file stem.

main.vyvyne
use "./math_utils.vy"; out(math_utils.double(7));

Or bind under an alias:

main.vyvyne
use "./math_utils.vy" as m; out(m.double(7));

use lib — external modules

use lib "..." loads an external module from the install directory. Paths are resolved relative to the vyne/modules/external/ folder in your Vyne installation.

deploy and dismiss

For lifecycle control of loaded modules:

Statement Effect
deploy name; Marks a module as used; makes its members visible.
dismiss name; Removes a module from the current scope.
In practice
The compiler resolves all imports at build time. deploy and dismiss are mostly relevant when writing tools that load Vyne modules dynamically; for typical programs, module and use are all you need.
Language Reference

Enums

Named Int64 constants. Auto-numbering with explicit overrides.

Syntax

enums.vyvyne
enum Direction { North, // 0 East, // 1 South = 10, // 10 (resets counter) West // 11 }; out(Direction.South); // → 10

Semantics

  • The backing type is always Int64.
  • Members are const — reassignment is a compile error.
  • An explicit = N resets the auto-increment counter from that point.
  • Enums are global. There is no namespacing beyond the enum name itself.

Using an enum

use-enum.vyvyne
heading :: Int64 = Direction.North; if (heading == Direction.North) { out("heading north"); };

Because enum members are plain Int64, you can store them in typed arrays, compare them with integers, and pass them anywhere an Int64 is expected.

Memory & Regions

The core of Vyne's memory model. Regions mark lexical scopes whose scratch allocations are released on exit.

The arena model

Every Vyne program runs on top of an arena — a bump allocator that hands out memory linearly and never calls free during the program's normal life. When you allocate something (an array, a string, a map, a struct), it goes at the current tip of the arena and the tip advances. That is the entire cost of allocation: a pointer bump and a bounds check.

Memory is released in bulk, not individually. A region is a marker: "everything allocated after this point is scratch, and I want it back when the block ends." On exit, the arena tip resets to where it was at region entry, and every allocation made inside is reclaimed in one operation.

No garbage collector
There is no GC. There is no reference counting during normal execution. There is only the arena and the region discipline you impose on it.

Region syntax

region.vyvyne
through i :: 1..10000 -> loop { region scratch { xs :: Array<Float64> = [1.0, 2.0, 3.0]; // ... heavy computation on xs ... }; // xs is gone. Arena tip is back where it was. };

Total memory usage stays flat across the loop, regardless of iteration count. Ten thousand iterations allocate the same arena bytes as one.

Nested regions

Regions nest. Each is a stack frame in the arena. Exiting the inner one releases only what the inner one allocated.

nested.vyvyne
region outer { a :: Array = [1, 2, 3]; // survives until outer closes region inner { b :: Array = [4, 5]; // released at inner close }; // b is gone, a is still alive };

Escaping a region: region.commit

If you need a value to survive past a region boundary, mark it with region.commit. This deep-clones the value into a separate arena that is not touched by region rewinds.

commit.vyvyne
lastMessage :: String = "initial"; through epoch :: 1..4 -> loop { region scratch { msg :: String = "epoch:" + string(epoch); lastMessage = msg; region.commit(lastMessage); }; out(lastMessage); // → epoch:1, epoch:2, epoch:3, epoch:4 };

Without the commit, the string allocated by "epoch:" + string(epoch) would be released when the region closed, and reading lastMessage afterwards would be a use-after-free.

Returning out of a region

The compiler handles return inside a region specially, depending on the return type:

Return type Behaviour
Int64, Float64, Bool, Null The value is copied by value; the region is rewound normally.
Everything else The region's checkpoint is popped from the stack without rewinding, so the arena memory remains live for the caller to read. The enclosing region (if any) will eventually rewind.

Observability

vmem.total_allocated() reports the total number of bytes the arena has handed out. It is monotonic within a region and drops back to zero after a rewind. Use it to verify that your regions are actually keeping memory flat:

verify.vyvyne
module vmem; before :: Int64 = vmem.total_allocated(); through i :: 1..1000 -> loop { region r { xs :: Array = [1, 2, 3, 4]; }; }; after :: Int64 = vmem.total_allocated(); out(after - before); // → 0, if the region works

What you cannot rely on

  • Exact byte counts. The arena rounds allocations up to 8-byte boundaries and reserves entire blocks for its internal bookkeeping. total_allocated() is useful for verifying flatness, not for precise measurement.
  • Aliasing across a rewind. Any pointer into arena memory that was allocated inside a region becomes invalid when the region closes. The compiler prevents this for variables it can trace, but it cannot catch every case — for example, a pointer smuggled into a struct field that outlives the region.
  • Commit-arena growth. Every region.commit call clones its argument into the commit arena, which is only freed at program exit. Committing inside a hot loop grows the commit arena linearly with iterations.
Commit in a hot loop
If you write region.commit(x) inside a loop that runs a million times, the commit arena will hold a million clones by the time the loop ends. Only commit values that genuinely need to outlive the region, and prefer to commit outside the loop when possible.

Error Handling

try, catch, finally, throw, and defer.

try / catch

try must be followed by catch, finally, or both. The catch variable is bound in a scope visible only inside the catch block.

try.vyvyne
try { risky(); } catch (err) { out("caught: " + err); };

If you do not name the error variable, it defaults to _err:

try-implicit.vyvyne
try { risky(); } catch { out(_err); };

finally

finally always runs — whether the try succeeded, was caught, or is propagating a new error. Use it for cleanup that must happen unconditionally.

finally.vyvyne
try { open_connection(); do_work(); } catch (err) { out("error: " + err); } finally { close_connection(); };

throw

throw accepts an optional expression. Throwing with no argument passes null to the catch block.

throw.vyvyne
if (x < 0) { throw "negative value not allowed"; }; // Bare throw — passes null throw;

defer

defer stmt; queues a single statement to run when the enclosing function exits. Defers run in reverse order of declaration.

defer.vyvyne
fn process() { defer cleanup(); defer log("done"); // ... work happens here ... // on exit: log("done"), then cleanup() };
defer placement
defer is only supported at the top level of a function body. Nesting it inside an if, loop, or region is a compile error.

Interaction with regions

When a function returns from inside a region, the region is unwound before the caller sees the return value. If the return value is non-primitive, the region is popped without rewinding — see Memory & Regions for the full rule.

When a function returns from inside a try block, the finally clause runs first.

Current limitations

  • break and continue cannot exit a try block.
  • There is no way to re-throw the current exception with a fresh stack — throw err; works, but the stack context of the original throw is not preserved.
  • Exceptions are values, not types. Any VyneValue can be thrown; there is no exception class hierarchy.
Language Reference

Built-in Functions

Always in scope. No module statement needed.

out

out(value); — writes the value to stdout followed by a newline. Accepts any VyneValue. Multiple arguments are allowed and each is printed on its own line.

string

string(v) -> String — converts any value to its display representation. Inverse operations are int64() and float64().

int64 and float64

int64(v) -> Int64 and float64(v) -> Float64. Both accept numbers or strings. Parsing failures throw a runtime error.

type

type(v) -> String — returns the runtime type name of a value as a string: "Int64", "Array", "Map", and so on.

sizeof

sizeof(v) -> Int64 — for arrays and strings, the element count or length. For maps, the number of entries. For primitives, always 8.

sequence

sequence(start, end) -> Array — returns a half-open array [start, start+1, ..., end-1]. Note that this differs from the .. range operator, which is inclusive.

map

map() -> Map — allocates a fresh empty map. Equivalent to writing {}.

exit

exit(code); — terminates the program immediately with the given exit code. Bypasses any active defers or finally blocks.

free

free(v); — a no-op in the current compiler. Because Vyne uses arena allocation and regions, individual values cannot be freed. The function exists for source compatibility with earlier drafts; the emitted C contains only a comment. Do not use it in new code; rely on regions instead.

free() does nothing
In the current backend, free(v) is compiled to a comment. It does not release memory. Do not depend on it, and do not expect C semantics.
Language Reference

Rulesets

Compile-time and program-wide configuration. Three flags are currently implemented.

Syntax

A ruleset is written at the top of a file, before any executable code:

ruleset.vyvyne
ruleset { dynamic_casting }; ruleset { warnings }; // ... your program ...

Or with a value:

ruleset-value.vyvyne
ruleset { memory_limit = 268435456 }; // 256 MB

Available flags

Flag Form Effect
warnings flag or warnings = "all" \| "none" \| "error_only" Enables diagnostic output. Without this, warnings are suppressed and only errors surface.
dynamic_casting flag Relaxes type checking. Type annotations on variables become optional and implicit conversions are permitted. Do not use in production.
memory_limit flag or memory_limit = <bytes> Enables the memory-usage check hook. Currently reports but does not enforce. Reserved for a future runtime check.

Strict mode

By default, Vyne operates in strict mode: every variable must have an explicit :: Type annotation, and every assignment is type-checked against the declared type. The dynamic_casting flag is the only way to relax this, and it is intended for scripts and one-offs.

Warning control

When warnings is enabled, the compiler reports unused variables, shadowed variables, and a few other patterns. The granular ignore list form is:

ignore.vyvyne
ruleset { warnings = "all", warnings_ignore = ["unused_variable", "shadow_variable"] };

Arithmetic

All arithmetic follows IEEE-754 for Float64 and two's-complement wraparound for Int64. Division and modulo by zero are runtime errors that terminate the program with a message.

** always produces a Float64 result, even for two Int64 operands. This matches the underlying pow() semantics and avoids the awkwardness of integer exponentiation overflow.

Logical

Short-circuit. The right-hand side is not evaluated if the result is already determined by the left. Any truthy value short-circuits ||; any falsy value short-circuits &&.

Special assignment forms

Operator Meaning
??= Assign if current value is null
++ / -- Postfix increment / decrement on numeric lvalues

Reference operators

& and $ are related to pass-by-reference parameters. See the Functions chapter for usage; the parser recognises them but the C backend currently rejects reference variables at compile time.

Reading a diagnostic

Every diagnostic in the terminal is printed with:

  • The severity (error, warning, note, perf hint).
  • The error code, which you can look up here.
  • The message text.
  • The source location, in file:line form.
  • A three-line excerpt from the offending file with a caret pointing at the column.
  • Zero or more suggestions, when the compiler has a specific fix in mind.

If you see an error that is not in this list, please open an issue — an undocumented error code is a bug in the documentation, not in your code.
